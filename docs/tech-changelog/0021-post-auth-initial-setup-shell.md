## 변경 사유 (Why)

로그인 또는 회원가입 직후 사용자의 초기 설정 완료 여부에 따라 홈과 초기 설정 화면을 구분할 수 있는 흐름이 필요했다. 다만 현재 배포 API와 생성 타입에는 최신 `onboarded` 계약이 없을 수 있어, 기존 생성 파일이나 오래된 엔드포인트를 변경하지 않고 이후 API 어댑터를 연결할 수 있는 UI 경계를 먼저 마련했다.

## 변경 내용 (What)

- 인증 성공 결과를 `AuthPage`에서 앱으로 전달하고, 데모 사용자와 `onboarded` 상태를 해석하는 앱 라우팅 함수를 분리했다.
- `/initial-setup` 경로에 설명 분야, 보유 자산, 간편 위험성향 진단 순서의 3단계 화면 골격을 추가했다.
- 한 번에 한 단계만 표시하며 진행률, 이전, 다음, 단계별 건너뛰기를 제공한다.
- 입력 초안과 건너뛴 단계를 분리해 보관하며, 건너뛰기만 한 항목에는 임의 기본값을 만들지 않는다.
- 자산 입력 필드는 해외주식, 외화예금, 원화 자산을 받는 공용 컴포넌트로 분리했다. 값의 합산·환산은 수행하지 않는다.
- 저장소에 Q1~Q3 질문 문구가 없어 코드와 화면에 계약 대기 상태를 표시했다. 질문·선택지·점수·성향 유형은 생성하지 않았다.
- 360px 이상 모바일 레이아웃과 `prefers-reduced-motion` 대체 스타일을 추가했다.

## 영향 / 리스크

- 현재 `TokenResponse` 생성 타입에는 `onboarded`가 없다. 런타임 인증 응답 또는 후속 어댑터가 `onboarded`를 제공할 때 분기가 동작하며, 값이 없으면 기존 흐름과 같이 홈으로 이동한다.
- 초기 설정 완료 콜백은 화면 경계까지만 존재하며 서버 저장을 호출하지 않는다. 최신 저장 계약이 확정되면 이 콜백에 API 어댑터를 연결해야 한다.
- Q1~Q3 원문과 선택지 계약이 없으므로 진단 단계의 다음 버튼은 비활성화된다. 사용자는 해당 단계를 건너뛰어 홈으로 이동할 수 있다.
- 기존 제품 소개용 `OnboardingTour`는 변경하지 않았다.
- 금융 수치, 위험 점수, 성향 유형 계산은 추가하지 않았다.

## 변경 사유 (Why)

기존 화면은 사용자 흐름을 검증하기 위한 목 데이터 중심이어서 실제 백엔드 계약의 인증, 응답 envelope, 오류 상태를 확인할 수 없었다. 또한 화면에서 임시 계산을 계속 사용하면 백엔드 결과와 달라질 수 있으므로, Swagger 계약을 단일 API 경계에 반영하고 실제 응답과 체험용 fixture를 명확히 구분할 필요가 있었다.

## 변경 내용 (What)

- \`VITE_API_URL\`을 기준으로 요청 URL을 만들고, \`{ data, meta }\` 응답 해제와 snake_case/camelCase 변환을 \`api/client.ts\` 한 곳에서 처리한다.
- 로그인·회원가입·데모 인증과 토큰 저장소를 연결하고, 사용자가 목 데이터와 API 데이터를 명시적으로 전환할 수 있게 했다.
- 홈, 환율 범위, 자산 분석, 플래너, 마이페이지별 API 모듈과 container hook을 추가했다.
- 각 화면에 loading/error/empty/success 상태를 두고 서버 오류를 목 데이터로 대체하지 않도록 했다.
- 기존 플래너 Curve와 시나리오 등 Swagger에 계약이 없는 기능은 목 데이터 체험에 남기고 화면에서 출처를 표시했다.
- 기존 데모 화면의 표시값을 전용 fixture로 이동하고, API 화면에서는 서버가 반환한 금액·비율·회차를 포매팅만 해 표시한다.

## 영향 / 리스크

- API 모드에서는 인증 토큰이 필요한 사용자 API에 Bearer 토큰을 전송한다. 세션이 만료된 뒤 자동 재시도 정책은 아직 연결하지 않았으므로 재인증 흐름을 후속 결정해야 한다.
- 2026-09-07 실서버 확인 당시 \`/api/v1/forecast\`, \`/api/v1/xray\`, \`/api/v1/xray/attribution\`, \`/api/v1/fit/concentration\`은 서버 500 응답을 반환했다. 프론트는 해당 메시지를 오류 상태로 표시하며 임의 값을 생성하지 않는다.
- 소셜 로그인, 이메일 중복 확인, 휴대폰 인증, 플래너 Curve 좌표·대체 시나리오, 목표 생성 계약은 현재 Swagger에 없어 실제 API 동작으로 연결하지 않았다. 휴대폰 인증 UI에는 체험용임을 표시했다.
- 금융 계산식과 수치 산식은 추가하거나 변경하지 않았다.

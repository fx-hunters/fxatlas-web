## 변경 사유 (Why)
프로젝트에 코드 스타일·테스트·Git 규칙은 있었지만, "어떻게 설계하고 어떤 코드를
좋은 코드로 볼지"에 대한 기준이 문서화되어 있지 않았다. 에이전트와 팀원이 코드
작성·리뷰·리팩토링 시 일관된 기준을 우선 적용하도록, 클린 코드·아키텍처 원칙을
전역 지침(AGENTS.md)에 명문화한다.

## 변경 내용 (What)
- AGENTS.md에 `## 7. 클린 코드 및 아키텍처 설계 원칙` 신설 (7.1~7.9):
  레이어링(단방향 의존성), 컴포넌트 설계(Container/Presentational·SRP), Custom Hooks,
  TypeScript 엄격성, 상태 관리(colocation·서버/클라 구분), 함수 클린 코드,
  네이밍(FE 보강), 에러 처리, 성능 최적화(과최적화 경계).
- 각 원칙에 요약 + ❌/✅ 스니펫 + 강제 수단(ESLint 규칙명/tsconfig 옵션) 포함.
- 섹션 상단에 "코드 작성·리뷰·리팩토링 시 반드시 우선 적용" 강제 문구 추가.
- 기존 섹션 번호 이동: 테스트→8, Git→9, 변경로그→10, 미확정→11. 교차참조 갱신.
- §11(미확정)에 §7 강제용 ESLint/tsconfig 확장 도입 결정 항목 추가.

## 영향 / 리스크
- 코드 규칙만 추가한 문서 변경으로 런타임·빌드 영향 없음.
- 문서가 권장한 ESLint 플러그인/규칙(import·naming-convention·타입체크 기반 등)은
  아직 미설치. "권장"으로 표기했고 실제 도입 여부는 §11에서 팀이 결정한다.
- 네이밍은 기존 §4·개발 컨벤션 4.1과 중복되지 않도록 FE 특화만 보강했다.

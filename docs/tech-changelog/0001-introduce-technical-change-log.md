## 변경 사유 (Why)
단위적·기능적 변경이 늘어날수록 "왜 이렇게 바꿨는지"가 코드와 커밋만으로는 흩어져
추적이 어렵다. 특히 계산·API 계약처럼 다른 화면/발표 자료와 연동되는 변경은 사유가
남지 않으면 나중에 되돌리거나 재검토할 때 근거를 잃는다. 변경 사유를 정해진 템플릿으로
한 곳에 축적해 추적 가능하게 만든다.

## 변경 내용 (What)
- `docs/tech-changelog/` 디렉토리 신설
- `TEMPLATE.md` (변경 로그 표준 양식), `README.md` (작성 규칙·목록) 추가
- 에이전트 규칙 문서(AGENTS.md)에 "기술적 변경 로그" 섹션을 추가해 작성 의무를 명시

## 영향 / 리스크

- 순수 문서/포맷팅 변경은 작성 대상에서 제외하므로 과도한 부담은 없다.
